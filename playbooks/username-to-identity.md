# Username to identity

Identity-focused collection requires explicit authorization covering the person, username or alias, purpose, and allowed sources. Apply strict minimization: collect only what answers an intelligence requirement, and do not retain unnecessary sensitive personal data.

## Passive workflow

Search public profile and account-existence indicators, public professional footprints, public aliases, and authorized email-presence signals. Sherlock, Holehe, Maigret, or similar tools may run only in Docker and only within the approved passive scope. Do not log in, trigger password resets or verification messages, send messages, bypass privacy controls, or infer private attributes.

Treat username reuse as a lead, never identity proof. For each candidate, record the exact public observation, source, timestamp, account URL, distinguishing attributes, and false-positive checks. Require independent corroboration before deriving an identity relationship; agreement between tools using the same upstream data is not independence. Never merge identity entities solely because they share a username.

Separate account existence, alias association, identity attribution, and assessment. Record alternatives and unknowns. Redact personal data and secrets. If approved sources provide no usable evidence, record exactly `no data found`; do not claim the account or person does not exist.
